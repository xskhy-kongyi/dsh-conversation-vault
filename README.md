# 会话仓库（Session Vault）

给 DeepSeek Harness 的侧栏对话一个“收起来”的去处，以及一个**只删对话、绝不删文件**的删除；
并把一段长对话蒸馏成可编辑、可被后续会话读取的**记忆卡**。

## 功能

- **彻底收起**：把对话从工作区摘下（detach），从此不出现在任何官方列表里，只在「会话仓库」可见。
- **归档管理**：官方归档的对话集中在一页，按原工作区分组，可整组清空、可折叠。
- **只删对话**：删除时只移除会话日志，不动任何文件或文件夹；正在跑回合的对话、有分叉子会话的对话会被拒绝。
- **对话仓库页**：和「插件市场」并排的一个面板；每行可重命名（走官方接口，侧栏同步）、恢复、删除。
- **记忆卡**：把长对话蒸馏成一篇 Markdown 经验文档，页面里可编辑；模型可在**任何**会话里用 `memory_card` 工具读取、检索、追加。
- **两种蒸馏**：右键菜单的「蒸馏成记忆卡」生成粗草稿；对话里说“把 XX 那次蒸馏成卡片”，由模型读素材后重写。

## 安装

```sh
# 从 npm
dsh plugin --profile <profile> add @kongyi/dsh-session-vault

# 或直接从 GitHub
dsh plugin --profile <profile> add github:kongyi/dsh-session-vault
```

安装后：

- 侧栏对话行的「…」菜单会多出三项（彻底收起 / 蒸馏成记忆卡 / 删除对话）；
- 左侧面板列表多一个「会话仓库」图标；
- 模型多一个 `memory_card` 工具（list / read / save / append / sessions / fold）。

## 数据放在哪

记忆卡是用户数据，存在：

```
~/.dsh/storages/session-vault/cards/*.md
```

`DSH_HOME` 存在时以它为准。早期版本写在插件目录里的卡片会在首次加载时自动迁移过去。

## 限制

- 归档会停止该对话正在进行的工作（官方语义）。
- 删除不重建搜索索引——但搜索后端每次查询前会对账，已消失的会话会被自动清掉。
- 对话式蒸馏的质量取决于会话日志；注入的运行时上下文会被过滤，极端情况下仍可能混入。
- HTTP 路由只监听本机，未额外鉴权。
- 记忆卡没有硬性字数上限，但单张过长会占用模型上下文；建议主卡精炼、细节放附录。
