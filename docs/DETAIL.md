# 会话仓库

一个面板，两种收起方式：**彻底收起**（本插件自己的）和**归档**（官方那套），删除只删对话、不动文件。

## 怎么用

鼠标移到侧栏任意一条对话上，点行尾的「…」（或直接右键那一行），打开的是**官方那个会话菜单**，里面多了两项：

- **彻底收起（只在会话仓库可见）**：把对话从工作区摘下来（detach），进会话仓库的**隐藏区**。它不再属于任何工作区，官方列表里再也看不到，只有这里能找到。
- **删除对话（保留文件）**：只删对话记录，不删任何文件。

菜单本身是官方组件，定位、键盘、关闭都由它负责，插件只贡献数据行，因此**不会在会话行上新增任何图标**。归档继续用官方那个收纳箱图标。

## 会话仓库页

- **隐藏区**：本插件收起的对话，按原工作区分组。
- **归档区**：官方归档过的对话，按原工作区分组，每组有「清空这一组」。
- 每行显示：状态、时间、占用大小，以及**恢复** / **删除**。
- 界面跟随系统语言（中文 / English）。

## 恢复

- 归档项：取消归档，回到原来在工作区里的位置。
- 隐藏项：挂回它原来的工作区。
- 如果原来的工作区目录已经被删掉或改名，恢复时会让你**手动选一个工作区**再挂回去。

## 为什么归档区不按「手动/自动」分

归档数据里只有一串会话 id，**没有记录"谁归档的"**（`workspace.json` 里的 `archivedSessionIds` 就是一个字符串数组，没有来源字段）。所以无法可靠区分"我手动归档的"和"别的插件自动归档的"。

替代方案是按**会话所属的工作区**分组：别的插件产生的对话通常集中在它自己的那个工作区里，天然独立成一组，一眼就能认出来并整组清理。

## 侧栏里还看得到归档对话？

侧栏是否显示归档对话，由侧栏对话列表右上角的「视图选项」（滑杆图标）→ 筛选控制：

- **隐藏已归档**：归档后彻底不显示（大多数人想要这个）
- **全部对话（显示已归档）**：归档后还在列表里，但点不开
- **仅显示已归档**：只看归档的

## 边界与限制

- 归档会停止该对话正在进行的工作（官方语义），被停掉的工作不会自动继续。
- 已归档的对话在侧栏点不开（官方行为），要打开先恢复。
- **正在跑回合的对话不能被收起**（提示先停掉它）。判定标准是会话 Agent 的 `status === 'running'`（正在跑一个回合，或正等你回答），**只是开着、闲着不算**。
- **正在跑回合的对话不能被删除或收起**（同上判定）。只是开着、闲着都不拦：DSH 会长期保留最近打开会话的 Agent，切走也不释放，所以"先关掉再删"是做不到的。删完如果那个窗口还开着，刷新页面即可（否则在那边继续发言会写入失败）。
- **有分叉子会话的对话不能被删除**（会提示还有 N 个子会话，先删子会话），避免留下指向不存在父会话的断链。
- 删除不会残留搜索索引：搜索后端在每次查询前会对账，已消失的会话会被从索引里删掉（源码 `_reconcile → _deleteSession('persisted', …)`）。
